## Overview

`local_trig_coinc` implements a **local-vs-local trigger coincidence algorithm** inside the MTRG Main FPGA. It is one of the 8 trigger algorithm slots instantiated in `top.vhd`. Its purpose: fire a trigger only when two independently-selected trigger algorithm acknowledgments overlap within a programmable time window.

Instead of responding to multiplicity sums from the detector array, this algorithm watches the acknowledgment outputs of any two other trigger algorithms already defined in the system (e.g., "fire only when both a SumX trigger AND a CPLD fast-sum trigger occur within N×20 ns of each other").

## Key Functionality

### Dual-mask selection
Two independent 7-bit mask registers (`OTHER_TRIGGER_MASK1`, `OTHER_TRIGGER_MASK2`) select which trigger algorithm acknowledgments contribute to each leg of the coincidence:

| Mask bit | Selects (from `OTHER_NONVETOED_TRIG_ACK[7:1]`) |
|----------|----------------------------------------------|
| bit 1 (mask bit 0) | Ack #1: Manual / NIM-IN / Target Wheel trigger |
| bit 2 (mask bit 1) | Ack #2: SumX trigger |
| bit 3 (mask bit 2) | Ack #3: SumY trigger |
| bit 4 (mask bit 3) | Ack #4: SumXY trigger |
| bit 5 (mask bit 4) | Ack #5: CPLD fast-sum trigger |
| bit 6 (mask bit 5) | Ack #6: GITMO or Remote Master trigger |
| bit 7 (mask bit 6) | Ack #7: Remote Master trigger |

✅ verified 2026-04-24 — local_trig_coinc.vhd:L113-121 (OTHER_TRIG_SEL_PROC: exact comment text for each bit confirmed, mask(i)(1)=ack#1 manual/NIM/TargetWheel, mask(i)(2)=SumX, mask(i)(3)=SumY, mask(i)(4)=SumXY, mask(i)(5)=CPLD fast sum, mask(i)(6)=GITMO/Remote Master, mask(i)(7)=Remote Master)

The OR of all selected acks (masked by `OTHER_TRIGGER_MASK(0)`) forms `MASKED_OTHER_TRIGGER(0)` — leg 1 of the coincidence. Similarly for `OTHER_TRIGGER_MASK(1)` / `MASKED_OTHER_TRIGGER(1)` — leg 2.

Both legs are generated by a `generate` loop creating two identical `OTHER_TRIG_SEL_PROC` processes. ✅ verified 2026-04-24 — local_trig_coinc.vhd:L107-128 (`OTHER_BLK: for i in 0 to 1 generate`; both use the same process body, assigned to `MASKED_OTHER_TRIGGER(i)`)

### Overlap / coincidence logic
The two masked trigger legs are fed into an `overlap_mach` instance (same module used in RTRG). The programmable `OVERLAP_DELAY[6:0]` (VME register, in 20 ns steps) sets the coincidence window. The `overlap_mach` produces:
- `T1_NO_OVERLAP`: leg 1 fired but no coincidence
- `OVERLAP_TRIGGER`: coincidence occurred → **this is the trigger condition**
- `T2_NO_OVERLAP`: leg 2 fired but no coincidence

Only `OVERLAP_TRIGGER` is passed to the generic trigger support module. ✅ verified 2026-04-24 — local_trig_coinc.vhd:L143 (`TRIG1_ONLY => T1_NO_OVERLAP`), L144 (`OVERLAP_EVENT => OVERLAP_TRIGGER`), L145 (`TRIG2_ONLY => T2_NO_OVERLAP`); L161 (`TRIGGER_OCCURRED => OVERLAP_TRIGGER` in U2 port map)

### Generic trigger support (`trig_algo_support`)
All algorithm-specific logic ends at `OVERLAP_TRIGGER`. The rest is handled by `trig_algo_support` (instantiated as `U2`), which is the standard wrapper shared by all MTRG trigger algorithms. It provides:
- FIFO management (trigger event FIFO)
- Prescaling (`TRIGGER_PRESCALE[15:0]`)
- Self-veto holdoff (`TRIGGER_HOLDOFF`, `TRIG_HOLDOFF_ENBL`) — added 2025-10-22
- Enable/veto gating
- Trigger monitor FIFO (shadow FIFO for TAC-II data collection)
- Acknowledgment outputs: `RAW_NONVETOED_TRIG_ACK`, `ENABLED_TRIG_ACK`, `ENABLED_NONVETOED_TRIG_ACK`
- Throttle request: `ALGO_THROTTLE_REQUEST` (half-full FIFO → throttle)
- `EVENT_AVAILABLE` → signals to master trigger collector

## Design Notes

- Trigger enable is enforced in `OTHER_TRIG_SEL_PROC`: if `TRIGGER_ENABLE='0'` or `RST='1'`, both masked legs are forced to 0 (no spurious coincidences during startup). ✅ verified 2026-04-24 — local_trig_coinc.vhd:L110-111 (`if ((TRIGGER_ENABLE = '0') OR (RST = '1')) then MASKED_OTHER_TRIGGER(i) <= '0'`)
- `overlap_mach` fires `OVERLAP_TRIGGER` immediately when the second leg arrives, even if the first is still asserted (changed 2015-09-10). ✅ verified 2026-04-24 — local_trig_coinc.vhd:L144 (`OVERLAP_EVENT => OVERLAP_TRIGGER, --OVERLAP_TRIGGER changed to occur immediately upon receipt of 2nd input 20150910`)
- `T1_NO_OVERLAP` and `T2_NO_OVERLAP` outputs are available but not used internally — connected to `open` in the port map, available for chipscope diagnostics if needed. ✅ verified 2026-04-24 — local_trig_coinc.vhd:L141-142 (`TRIG_DIAG_1 => open`, `TRIG_DIAG_2 => open`); note these are the overlap_mach diagnostic outputs, not T1/T2_NO_OVERLAP — those are assigned to signals but not connected to ports (T1_NO_OVERLAP, T2_NO_OVERLAP declared as local signals at L71-72, not driven anywhere externally)
