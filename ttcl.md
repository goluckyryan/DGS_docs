## 1. Overview

The **Trigger Timing and Control Link (TTCL)** carries timestamps, trigger messages, and system-wide commands between trigger and digitizer modules in GRETINA, Digital Gammasphere (DGS), DFMA, and MAJORANA systems.

- Physically: 1 Gbps serial link using SERDES chip (serializer/deserializer)
- Generated by the **Master Trigger** of each system
- Propagated down: Master Trigger → Router Triggers → Digitizers
- Master + Router Triggers = **Trigger Timing & Control System (TTCS)**

### Key modules

| Module | Role |
|--------|------|
| Master Trigger (MTRG) | Generates TTCL, top of hierarchy |
| Router Trigger (RTRG) | Re-propagates TTCL to digitizers |
| Digitizer (DIG) | Receives TTCL, acts on commands |
| MγRIAD | Propagates TTCL to auxiliary detectors; single connection only (no re-propagation) |
| GITMO | Gammasphere Interface — distributes clocks/triggers from analog GS to DGS MTRG |

## 2. Physical Specification

### 2.1 Master and Router Trigger

- **Connectors:** Hard metric, 2mm pitch, IEC 61076-4-101
- **Cable:** Twisted pair, 100 Ω characteristic impedance
- Physically intermingled with the Trigger Data link (one TTCL + one Data link per front-end board)

**IEC 61076-4-101 connector pinout (25-row, 5-column a–e):**
- Rows/columns carry: Data In ± (a/b), GND/SHLD (c), TTCL Out ± (d/e)
- Signals: LVDS differential pairs for both data and TTCL

### 2.2 Digitizer, Digitizer Tester, GITMO and MγRIAD

- Single bi-directional SERDES link → uses **RJ45 connector** (not Ethernet-compatible!)
- No built-in termination — discrete passives on PCB handle it
- **RJ45 pinout** *(full pinout in `connectors.md`)*:
  - Pin 7/8: SERDES RX+/− : TTCL in (from trigger to digitizer)
  - Pin 3/6: SERDES TX+/− : Trigger Data Link (digitizer → trigger system)
  - Pin 1/2: Auxiliary In0 +/− (LVDS1 — fast discriminator copy / multiplicity in GRETINA; undefined in DGS)
  - Pin 4/5: Auxiliary In1 +/− (LVDS2 — throttle request)
    - GRETINA: LVDS1 = fast discriminator copy (multiplicity), LVDS2 = throttle request
    - DGS: LVDS2 = throttle request; LVDS1 not defined

## 3. Electrical Specification

### 3.1 Chipset

- **SERDES:** National Semiconductor DS92LV18 ✅ verified 2026-04-12 — DGS_SVN BOM (U24–U31,U35–U37: DS92LV18TVV)
- **Physical interface (cable driver/receiver):** National Semiconductor DS90LV004 ✅ verified 2026-04-12 — DGS_SVN BOM (U20–U22: DS90LV004TVS)

### 3.2 Timing

- **Clock:** 50.000 MHz parallel word input clock → **1 Gbps** serial bit stream (×20) ✅ verified 2026-04-18 — SERDES chip is DS92LV18TVV (National Semiconductor, rated 1 Gbps LVDS), verified from DGS_SVN BOM (connectors.md:L41); 50 MHz × 20-bit parallel word = 1000 Mbps confirms the 1 Gbps figure
- Clock edge transitions buried in the serial data in the two "extra" bits between word boundaries allow the SERDES receiver to regenerate a matched clock
- PLL capture range: ±5% frequency variation (if drift is slow vs. clock period)
- **Master Trigger must have a stable, low-drift clock source**

### 3.3 Jitter Budget

- In large systems (DGS/DFMA), accumulated jitter across many TTCL "hops" can cause data errors
- Recommendation: **total accumulated jitter < 250 ps** at the far end
- Per-board jitter budget: **< 50 ps** (requires careful power supply filtering on each board's clock mux)

### 3.4 LVDS Signal Levels

- 100 Ω odd-mode characteristic impedance; 100 Ω terminating resistor across conductor pair
- Typical LVDS current: 5 mA → ~500 mV differential at receiver
- Shielded cables or pre-emphasizing drivers required for cable lengths > 10 m

### 3.5 PCB Layout

- Differential traces must be very well length-matched
- Vias, package pins, and even connector pin length mismatches all matter at 1 Gbps
- Both boards at each end of a cable must be co-designed for pin length matching
- Reference: National Semiconductor LVDS Owners Manual, Chapter 3

## 4. Systems That Use the TTCL

### 4.1 GRETINA

- GRETINA uses a hierarchical trigger: Master Trigger → Router Triggers (up to 4 per crate) → Digitizers
- Each crate has one Router Trigger connected to the Master Trigger via TTCL
- Digitizers connect to Router Triggers via RJ45
- TTCL fan-out follows the physical crate hierarchy

**GRETINA hierarchical trigger implications:**
- TTCS: one Master Trigger + tree of subsidiary Router ("slave") trigger modules
- All TTCL info is originally sourced by the Master; Routers receive and re-transmit without modification
- Up to 8 Routers per Master; each Router fans out to up to 8 Digitizers
- GRETINA: 4 of 8 master outputs used; 4 of 8 inputs used (per Figure 3)
- Expandable to 3-level hierarchy for full GRETA (128 front-end digitizers)

### 4.2 DGS/DFMA

**DGS/DFMA-specific modules:**
- **GITMO (Gammasphere Interface Trigger Module):** Picks off signals from analog Gammasphere; provides auxiliary triggers + reference clock to the DGS Master Trigger via SERDES. Link format is **NOT** TTCL-compatible — DGS-specific. Master Trigger assumes any connection to link **L** is from a GITMO. (DFMA Master is more general — assumes TTCL format on link L.)
- **MγRIAD:** Provides auxiliary detector trigger connectivity to a Master Trigger. Can propagate timestamps/triggers to VME-based DAQs that don't use digitizers. Can monitor non-TTCL external detectors via NIM/ECL and send trigger messages back. Sends and receives in TTCL format. Normally connected to link **R** or **U** of a Master Trigger.
- **Digitizer Tester:** Test stand module — listens to TTCL and generates test waveforms to exercise digitizers. Not normally part of a detector system.

**DGS/DFMA link names (per system diagram):**
- A-H: Router-to-Digitizer TTCL links
- L: Master-to-GITMO / DFMA Master-to-Master link
- R, U: Master-to-MγRIAD links

**DGS and DFMA are independent hierarchies** that allow selective cross-triggering between systems (sharing clock and timestamp). Up to 8 Routers per Master.

### 4.3 Selective Propagation (DGS/DFMA only)

- New TTCL feature introduced for DGS/DFMA
- Defines what portions of TTCL data received by a Master Trigger over links L, R, U are allowed to propagate into the 'local domain' of that Master from outside
- Key use case: allow trigger decision messages from one Master (e.g., DGS) to propagate into another's domain (e.g., DFMA) — enabling cross-triggering between detector systems
- Requires correlated clocks and timestamps between the two systems

## 5. Theory of Operation

### 5.1 System Cycle Structure

- TTCS sends a command every **100 ns** (5 words × 20 ns/word at 50 MHz) ✅ verified 2026-04-07 — MTRG top.vhd:L177 (50 MHz logic clock), SERDES_RX_Mach_R2.vhd:L97 ("20 states, 5 words each")
- **System cycle:** 20 command frames = 100 words = **2 µs** total ✅ verified 2026-04-07 — MYRIAD_RCV_MACH.vhd:L72 + SERDES_RX_Mach_R2.vhd:L97
- Master triggers endlessly repeat this 2 µs cycle
- Some frames are mandatory (fixed position, every cycle); others are optional (replaced by null frame if not needed)
- Front-end devices **must not respond** to null command frames

### 5.2 System Cycle Breakdown

Key timing rules:
1. **Sync Frame** issued every 2 µs — provides overall system synchronization
2. **Trigger decision frames** always occur at the same positions within each cycle (deterministic, aids debugging)
   - Up to **8 triggers** may be issued per 2 µs cycle
   - Number of triggers is latched before the cycle begins
   - A trigger that "just misses" is delayed by 2 µs
3. **Trigger Data link** is also synchronized on a 2 µs clock
   - "Fast" data: constantly transmitted
   - "Slow" data: only sent in response to a TTCL command (demand front-end slow data)

### 5.3 System Timestamp

- 48-bit counter, incremented every **10 ns** (100 MHz) — the **System Timestamp** ✅ verified 2026-04-12 — RTRG/timestamp.vhd ("Big honkin' 48-bit counter") + router_top.syr (48-bit TRIG_TIMESTAMP register) + MTRG trigger_top_comp_defs.vhd:L161 (mclk_2x = 100 MHz)
- Broadcast regularly to all front-end electronics for event synchronization
- Serial link word rate is only 50 MHz, so: words are only loaded when the 100 MHz timestamp LSB = 0 (even number)
- Receivers must synchronize their clock multipliers so that any 100 MHz counter synthesized from the 50 MHz link clock has its LSB = 0 immediately after rising edges coincident with the link word clock rising edge

### 5.4 DGS and DFMA Timestamp Correlation

- DGS uses same Trigger + Digitizer modules as GRETINA but with significantly modified firmware
- DGS system has two DAQs: **DGS** and **DFMA** — both share the same clock and timestamp
- Major additions to the GRETINA TTCL allow the two systems to:
  - Cross-synchronize timestamps
  - Cross-trigger each other
  - Share the same 50 MHz clock

#### 5.4.1 Clock Synchronization with Analog Gammasphere in DGS

- GITMO sends a continuously repeating sequence of data words indicating the trigger state of analog Gammasphere
- DGS Master locks onto the GITMO clock (SERDES clock recovery) and runs synchronously with analog Gammasphere's clock
- Timestamps generated independently, but same clock frequency allows direct timestamp comparison between legacy and digital systems

## 6. Protocol Specification

Three layers: **Words** → **Frames** → **Cycles**
- 20 bits/word, 5 words/frame, 20 frames/cycle
- Each system cycle immediately follows the previous; data cycles continuously

### 6.1 Word Format

DS92LV18 sends 20-bit words. Bits 17 and 0 are special; **16 bits** are payload data:

| Bit | Name | Value | Description |
|-----|------|-------|-------------|
| A (msb) | Embedded clock edge | 0 | SERDES clock embedding |
| 17 | Edge Guard | 0 | Fixed 0; guard bit for reliable clock recovery |
| 16..1 | Data Payload | — | 16-bit data payload |
| 0 | Polarity Flag | 0 or 1 | DC balance flag |
| B (lsb) | Embedded clock edge | 0/1 | SERDES clock embedding |

#### 6.1.1 Embedded Clock

- SERDES converts 18-bit parallel words to 20-bit serial (2 extra bits embed clock transitions)
- Bit 17 fixed at '0' = guard bit ensuring reliable clock recovery at receiver

#### 6.1.2 DC Balance

- Modules may count 1s and 0s per word and choose to send "true" or "inverted" data in bits 16..1 to maintain DC balance
- **Bit 0 = Polarity Flag:** '0' = bits 16..1 are inverted (re-invert on receipt); '1' = data correct as received ✅ verified 2026-04-13 — `DCBAL_in_nofifo.vhd:L68` (`LATCHED_D_IN(0)='0'` → NOT, else pass-through)
- All modules **must** implement logic to receive DC-balanced data; transmitting DC-balanced data is optional ✅ verified 2026-04-13 — `dc_balance_mach.vhd:L31,L120` (TX has `enable` port; when disabled, data passes unchanged)

### 6.2 Frame Format

Each command frame = 5 × 18-bit words:

| Word | Bit 17 | Bits 16..9 | Bits 8..1 | Bit 0 |
|------|--------|------------|-----------|-------|
| 1 | 0 | Command Byte | Command Argument | Polarity Flag |
| 2 | 0 | Auxiliary Info | Auxiliary Info | Polarity Flag |
| 3 | 0 | Auxiliary Info | Auxiliary Info | Polarity Flag |
| 4 | 0 | Auxiliary Info | Auxiliary Info | Polarity Flag |
| 5 | 0 | Auxiliary Info | Auxiliary Info | Polarity Flag |

- Word 1: Command Byte (bits 16..9) + Command Argument (bits 8..1). The entire 16-bit word may also be treated as a single command.
- Words 2–5: Data associated with the command (command-dependent)

#### 6.2.1.1 Null Command

| Word | Bits 16..1 |
|------|------------|
| 1–4 | 0xAAAA |
| 5 | 0x0000 |

✅ verified 2026-04-13 — `SERDES_RX_Mach_R2.vhd:L237` (null frames defined as `0xAAAA×4 + 0x0000`; null detection L409 checks `LATCHED_CONTROL_DATA /= X"AAAA"`)

|--------------------|--------|
| 0x00 | Null — do nothing |
| 0x01 | Sync (check timestamp) |
| 0x02 | Debugging Control Command |
| 0x04 | Front end calibration inject | ✅ verified 2026-04-16 — `DIG/MAIN_FPGA/BuildBranches/DGS_TAG_20180607_TWEAK/DGS/Source/SERDES_RX_Mach.vhd:L305` (`when X"04" => CAL_INJECT_FLAG <= '1'`) |
| 0x08 | Latch Status & Monitoring Data | ✅ verified 2026-04-16 — `SERDES_RX_Mach.vhd:L308` (`when X"08" => LATCH_STATUS_FLAG <= '1'`) |
| 0x10 | Front End Reset | ✅ verified 2026-04-16 — `SERDES_RX_Mach.vhd:L311` (`when X"10" => FRONT_END_RESET_FLAG <= '1'`) |
| 0x18 | Front End Reset (serial links only) | ✅ verified 2026-04-16 — `SERDES_RX_Mach.vhd:L314` (`when X"18" => RESET_LINKS_FLAG <= '1'`) |
| 0x22 | External Discriminator Request (DGS, added 20160418) | ✅ verified 2026-04-16 — `DIG/MAIN_FPGA/BuildBranches/DGS_TAG_20180607_TWEAK/DGS/Source/SERDES_RX_Mach.vhd:L317` (`when X"22" => EXTERNAL_DISC_FLAG_PENDING <= '1'`; block added 20160418 comment at L278)

| 0x60–0x6F | Re-propagated trigger from Link L (remote algo type in low nibble) | ✅ verified 2026-04-17 — `remote_trig_support.vhd:L388`
| 0x70–0x7F | Re-propagated trigger from Link R/U (delay mode) | ✅ verified 2026-04-17 — `remote_trig_support.vhd:L411`
| 0x81 | Imperative Sync (force reload of timestamps). Two variants: `0x81FF` = with timestamp rollover; `0x8100` = no rollover. ✅ verified 2026-04-17 — `DIG/MAIN_FPGA/BuildBranches/DGS_TAG_20180607_TWEAK/DGS/Source/SERDES_RX_Mach.vhd:L582-586` |
| 0x90–0x97 | Auxiliary Detector command (reserved) |
| 0x98–0x9F | Main Detector Miscellaneous command (reserved) |
| 0xAA | Null — do nothing |
| 0xFF | End-of-Cycle (timing boundary marker only; no action) | ✅ verified 2026-04-13 — `SERDES_RX_Mach_R2.vhd:L244` FRAME 20 FIXED_BITS W1 = `X"FFFF"` → cmd byte bits 16..9 = 0xFF |

Undefined command byte received → receiver should NOT process it; report error to slow monitoring system (not to TTCS).

### 6.3 Cycle Format — 20-Frame Layout

*Italicized = mandatory (always issued, never replaced by null)*

| Frame | Start (ns) | End (ns) | GRETINA Purpose | DGS/DFMA / MAJORANA Purpose |
|-------|-----------|---------|-----------------|----------------------------|
| **1** | 0 | 100 | *Sync command* | *Sync command* |
| 2 | 100 | 200 | Unused (null) | Debugging Control Command |
| 3 | 200 | 300 | Trigger Decision | Trigger Decision |
| 4 | 300 | 400 | Trigger Decision | Trigger Decision |
| 5 | 400 | 500 | Trigger Decision | Trigger Decision |
| 6 | 500 | 600 | Trigger Decision | Trigger Decision |
| 7 | 600 | 700 | Trigger Decision | Selectively propagated Trigger Decision |
| 8 | 700 | 800 | Trigger Decision | Selectively propagated Trigger Decision |
| 9 | 800 | 900 | Trigger Decision | Trigger Decision |
| 10 | 900 | 1000 | Trigger Decision | Trigger Decision |
| 11 | 1000 | 1100 | Spare | Spare |
| 12 | 1100 | 1200 | Internal Trigger Command | Internal Trigger Command |
| 13 | 1200 | 1300 | Demand Front End Slow Data | Unused in DGS (checked by firmware) |
| 14 | 1300 | 1400 | (see below) | Internal Trigger Command (DGS/DFMA only) |
| 15 | 1400 | 1500 | Unused/reserved | Internal trigger commands to Digitizer Tester |
| 16 | 1500 | 1600 | GRETINA Front End Async cmd | Selectively propagated Trigger Decision |
| 17 | 1600 | 1700 | Aux Detector Reserved Command (null if not required) | Same |
| 18 | 1700 | 1800 | Spare (null) | Spare (null) |
| 19 | 1800 | 1900 | Spare (null) | Internal trigger reserved frame (null to all front ends) |
| **20** | 1900 | 2000 | *End-of-Cycle command* | *Synchronous System Capture command* |

**Frame category summary:**
- Frames 1, 20: Receiver machine synchronization + system timestamp propagation
- Frames 3–10: Trigger acceptance messages → cause event selection in digitizers
- Frames 12, 14: Reserved for internal use within trigger system
- Frame 13: GRETINA-specific data synchronization (DGS/DFMA digitizers don't use it but require correct format)
- Frames 15–17: Occasional non-repeating messages (broadcast slow control / synchronized control operations)
- Frames 2, 18, 19: Unused / spare

### 6.4 Selective Propagation (DGS/DFMA only)

Three **Propagation Control Registers** in each DGS/DFMA Master Trigger firmware:
- **Link L Propagation Control Register**
- **Link R Propagation Control Register**
- **Link U Propagation Control Register**

Each is **bit-mapped per-frame**. Each bit, if set, enables propagation of that frame from the remote source into the local system. Default at power-up: all bits = 0 (no propagation allowed).

| Bit | Frame | Description |
|-----|-------|-------------|
| F1 | 1 | (Link L only) Propagate Imperative Sync from remote Master; recommended to set in any Master receiving clock from another Master |
| F3–F10 | 3–10 | Propagate trigger decision frames from each link; enables cross-detector triggering |
| F11 | 11 | Reserved (spare) |
| F12 | 12 | Propagate Internal Trigger Frame (mainly for test stands) |
| F14 | 14 | Propagate Internal Trigger Frame to Digitizer Tester (fake events) |
| F16 | 16 | **Most commonly used (other than F1):** Propagate Synchronous System Capture Command across multi-detector system |
| F17 | 17 | Propagate Auxiliary Detector commands (control MγRIAD from top-level) |
| F18, F19 | 18, 19 | Reserved for future use |

**Cross-detector trigger propagation rules:**
- Re-propagated trigger decisions buffer in their own FIFOs and re-propagate during last 3 trigger decision frames:
  - Link L → Frame 8
  - Link R → Frame 9
  - Link U → Frame 10
- A link **cannot** re-propagate back the trigger decision frame assigned to itself (prevents deadly embrace)

## 8. Initialization Considerations

- At system startup, TTCS enters **initialization phase:**
  - Frames 1 and 20 driven normally
  - All other frames forced to Null
  - Persists until slow control releases the trigger
  - Normal operation begins with the next full trigger cycle (starting with Frame 1 Sync)
  - Reset of trigger repeats initialization
- **Note:** Initialization mode is being deprecated; Frame 2 (Debug Command) also being removed in a future revision

**What if TTCS must be reset?**
- Generally should never be required
- Recommended: power-cycle the crate, re-initialize links, resume operation
- Most likely failure mode: large trigger burst overflows a FIFO in the trigger path
- Individual algorithm FIFOs: reset by turning the algorithm off then on again
