## 1. Overview

The `CTL_FPGA_REGISTERS` entity is an Excel-VBA-generated register block for the
**Collector Box Control FPGA** (CtrlFPGA). It implements a 141-register interface
providing:

- **Control outputs** (write-only): pulsed resets, FPGA control, ILA mux, scanner ROM
  address, ADC transactor, DPRAM bank select
- **Status inputs** (read-only): firmware date/revision, GPIO readback, trigger clock
  counter, and all per-stripe ADC monitoring values
- **Sensor data** (read-only): DVI ground-fault current monitors (5 DVIs per stripe),
  48V current monitors, voltage rails, ADC self-calibration values
- **BGO FPGA** voltage monitoring (3.3V, 2.5V, 1.2V) via Stripe 6 region

The file uses the `ExcelGen_Package` (from `CtrlFPGA_registers_pkg.vhd`) and the
`array_of_REGISTER_CONFIG` type from an implicit ANL register framework.

## 4. Per-Stripe Monitoring Registers

All monitoring registers are **read-only** (write mask = 0x0000). Each stripe
provides 21 monitoring values. The order in the register table is:
**Stripes 1, 3, 5** (odd stripes, addresses ~128–191), then **Stripes 2, 4**
(even stripes, addresses ~192–233), then **Stripe 6** (addresses ~234–254).

This ordering matches the address layout documented in `collectorboxpi.md`
(stripe address assignments from `Non_EPICS_Globvars.c`).

### Per-stripe register pattern (repeated for each stripe N)

| Signal | Description |
|--------|-------------|
| `SN_DVI1_GndFault_I` | DVI channel 1 ground-fault current monitor |
| `SN_DVI2_GndFault_I` | DVI channel 2 ground-fault current monitor |
| `SN_DVI3_GndFault_I` | DVI channel 3 ground-fault current monitor |
| `SN_DVI4_GndFault_I` | DVI channel 4 ground-fault current monitor |
| `SN_DVI5_GndFault_I` | DVI channel 5 ground-fault current monitor |
| `SN_DVI1_48V_I` | DVI channel 1 48V current monitor |
| `SN_DVI2_48V_I` | DVI channel 2 48V current monitor |
| `SN_DVI3_48V_I` | DVI channel 3 48V current monitor |
| `SN_DVI4_48V_I` | DVI channel 4 48V current monitor |
| `SN_DVI5_48V_I` | DVI channel 5 48V current monitor |
| (UNUSED × 2) | Unused scanner slots |
| `SN_12V` | Stripe N 3.3V rail monitor (signal name vs. comment mismatch — see note) |
| `SN_25V` | Stripe N 2.5V rail monitor |
| `SN_33V` | Stripe N 1.2V rail monitor |
| (UNUSED × 1) | Unused scanner slot |

| `SN_ADC_VCC` | ADC N VCC supply monitor |
| `SN_ADC_TEMP` | ADC N internal temperature |
| `SN_ADC_GAIN` | ADC N gain calibration |
| `SN_ADC_REF` | ADC N reference voltage |

> **Note:** Signal name vs. comment mismatch in source — `SN_12V` is described in
> comments as "3.3V monitor", `SN_25V` as "2.5V monitor", `SN_33V` as "1.2V monitor".
> The naming appears inverted (probably a spreadsheet labeling artifact). The EPICS
> device support uses conversion factors from `Non_EPICS_Globvars.c` as ground truth
> for what each ADC channel actually measures.

## 5. Register Count and Addressing

- **Total registers:** 141 (indices 1–141 in the `array_of_REGISTER_CONFIG`)
- **Address format:** Partial hex nibble addresses shown in source (e.g., `X"9"`, `X"3"`)
  — full addresses are bank-qualified; the register framework (`a_to_i()` function)
  resolves them from the config array
- **All monitoring inputs** have full read mask (`0xFFFFFFFFFFFFFFFF`) and zero write mask
- **All control outputs** have specific write masks per signal, often restricting to
  meaningful bits only
